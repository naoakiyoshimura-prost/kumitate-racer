# バランス確認（組立てレーサー）

数値を変えたら、公開前にこの順で回す。合計およそ5分。外部サービスもAPIも使わない（ローカルの node だけ）。

## 手順

1. `npm run -s exsim`（約30秒）
   - EXあり/なしのタイム差をドライバーごとに見る。
   - **見る点:** EXによる短縮が、レイナ/ツバサのヘアピン（−11〜−14秒）を大きく超えていないか。大きく超えたドライバーがいれば強すぎ。
2. `npm run -s chassissim`（約1分）
   - 同じセッティングでシャーシだけ変えたときのコース別順位。
   - **見る点:** 1つのシャーシが全コースで1位になっていないか。4輪＝テクニカル有利、6/8輪＝高速有利の傾向が保たれているか。
3. `npm run -s searchbuild`（約3.3分）
   - ランダム構成のコース別上位と「標準」の順位。
   - **見る点:** 1つの構成（同じパーツの組み合わせ）が全コースの上位を総なめしていないか。標準セッティングが最強になっていないか（オーナー方針）。

## 報告

- 3本の要点を各1〜2行で。崩れていたら、どのパーツ・どのドライバーが原因かを名指しする。
- 数値の微調整はオーナーが JSON を直接いじる方針。AIは「どこがどれだけ強いか」を示すまでにし、勝手に何度も数値を回さない（docs/HANDOFF.md 6章）。
- searchbuild は重いので、途中で止めたり何度も回したりしない。1回の作業で1回まで。
