## 3. 技術と動かし方
- Three.js + TypeScript + Vite。サーバーなし（静的サイト）
- `main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）が GitHub Pages に自動公開
```sh
npm install
npm run dev      # 開発サーバー（--host 付きなので同じWi-Fiのスマホから開ける）
npm run build    # 型チェック + ビルド
npm run sim      # ライン取りの作戦別ラップ比較（数値調整用）
npm run cpusim   # CPUの強さ確認
npm run buildsim    # コース×代表セッティングのタイム、コースアウト、着地乱れ（バランス調整の基本）
npm run coursecheck # コースの長さ、最小半径（10m未満は要注意）、ジャンプ位置
npm run searchbuild # ランダム250通りのセッティングを走らせ、コースごとの上位と「標準」の順位を出す
npm run eventsim    # 大会ごとに、コスト制限内のランダム構成が大会CPUに勝てる割合と最速構成を出す
npm run chassissim # 同じセッティングでシャーシだけ変えたときのコース別タイム
npm run cornersim  # グリップ旋回とローラー旋回のセッティング比較
npm run exsim       # ボディごとに、EX技を使える瞬間に毎回使ったときのタイム（使いどころの確認）
```

## 4. 設計の要点（壊さないでほしいもの）
1. **見えないレール方式**：車は物理エンジンではなく、コース中心線のスプラインに沿って動く。位置は「進んだ距離 distance」と「横位置 lat（m、+が右）」の2つだけ
2. **旋回はガイドローラー任せ**：プレイヤーはハンドルを切らない。操作はレーン変更（左右）とブーストだけ
3. **遠心力で外へ流れる → 壁にローラーで当たる → 減速して壁沿いに曲がる / 強すぎるとコースアウト**。オーナー評価「流され具合が絶妙」。この感触は変えないこと
4. **数値はすべて `src/data/tuning.json`**、**コースは `src/data/*.json`**。ロジックに数値を直書きしない
5. **入力は操作命令に変換**（`src/input.ts` → `'left' | 'right' | 'boost' | 'transform' | 'ex'`）。CPU（`src/cpu.ts`）も同じ命令だけで走る。CPUにズルをさせない
6. **走行計算（`src/car.ts`）は見た目を持たない純粋な計算**。だから `tools/*.ts` でシミュレーションできる
7. **カメラは独立部品**（`src/camera.ts`）。後方視点はプリセットの1つ
8. **ジャンプは着地安定性で判定**：着地NGゾーンはない。着地の衝撃（落下速度・車速・タイヤ径）が「着地安定性」を超えると乱れ（減速＋横揺れ）、超えた量が大きいほどコースアウト確率が上がる。標準セッティングはわざと少し足りない（オーナー指定）
9. **重さのトレードオフ**：ウィング・マスダンパーなど安定装備は重くなり、加速と最高速が落ちる。プラスしかないパーツは作らない
10. **中央値（標準）セッティングを最強にしない**（オーナー方針）。パーツやコースを足したら npm run searchbuild で標準の順位と上位の顔ぶれを確認する。同じパーツが上位を独占していたら弱体化する
11. **スマホ優先**：横持ち、30fps以上。重い描画（影・ポストエフェクト）は入れない

## 6. 進め方のルール（オーナーの方針）
- **クレジット節約が最優先**。1回の依頼で1段階まで。段階が終わったら止めて報告し、オーナーの「進めて」を待つ
- 1つの依頼で1つの機能。変更のたびにビルドが通ることを確認してからコミット
- 同じ不具合に2回失敗したら、直前のコミットに戻す
- 数値の微調整はオーナーが JSON を直接いじる。AIに「いい感じに」を繰り返させない
- 公開リポジトリなので、**パスワード・APIキーは絶対にコードに入れない**
- 返答は日本語。辛口コメント＋根拠＋リスクとリスクヘッジを明示するスタイルが好まれる

## 8. 既知の課題
- セッティングのバランス（npm run buildsim）：ハイスピードは「最高速＋安定装備」が明確に有利、テクニカルは「標準」と「コーナー特化」が僅差、スタンダードは「標準」が最速。スタンダードで特化型の勝ち筋が弱い
- 最高速特化（安定装備なし）は着地で崩れて勝てない。これはオーナーの意図どおり
- テクニカルはCPUのコースアウトが多め（平均2.4回/2周）
- 上位セッティングに「3.55:1ギヤ」「高回転型」が多い（searchbuild）。テクニカルでも最高速寄り＋大径アルミが上位に来るので、テクニカルらしさが弱い
- 所持金・所持パーツは端末のlocalStorageだけに保存。改ざんは簡単なので、ランキングやピットボード連携の前にサーバー保存へ移す。通貨は有料販売しない（資金決済法・景品表示法のリスク、economy-spec.md）
- 大会の勝てる構成の割合は eventsim で数%〜20%程度。乱数の揺れが大きいので、調整時は2回以上回す
- EX技（ゲージ60に変更）はので、何も考えず毎回使うとブーストが減って遅くなることが多い（exsim）。テクニカルのドリフト・壁走りは明確に得。CPUはEXを使わない
- 変形はシミュレーション上、ハイスピードではブースト中心の方が速い（エアロ中はゲージが回復しないため）。CPUの変形の使い方は単純
