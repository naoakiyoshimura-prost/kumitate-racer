## 3. 技術と動かし方
- Three.js + TypeScript + Vite。サーバーなし（静的サイト）
- `main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）が GitHub Pages に自動公開
```sh
npm install
npm run dev      # 開発サーバー（--host 付きなので同じWi-Fiのスマホから開ける）
npm run build    # 型チェック + ビルド
npm run sim      # ライン取りの作戦別ラップ比較（数値調整用）
npm run cpusim   # CPUの強さ確認
npm run jumpsim  # 速度ごとのジャンプ飛距離
npm run buildsim # 代表的なセッティングの3周タイム比較
```

## 4. 設計の要点（壊さないでほしいもの）
1. **見えないレール方式**：車は物理エンジンではなく、コース中心線のスプラインに沿って動く。位置は「進んだ距離 distance」と「横位置 lat（m、+が右）」の2つだけ
2. **旋回はガイドローラー任せ**：プレイヤーはハンドルを切らない。操作はレーン変更（左右）とブーストだけ
3. **遠心力で外へ流れる → 壁にローラーで当たる → 減速して壁沿いに曲がる / 強すぎるとコースアウト**。オーナー評価「流され具合が絶妙」。この感触は変えないこと
4. **数値はすべて `src/data/tuning.json`**、**コースは `src/data/*.json`**。ロジックに数値を直書きしない
5. **入力は操作命令に変換**（`src/input.ts` → `'left' | 'right' | 'boost'`）。CPU（`src/cpu.ts`）も同じ命令だけで走る。CPUにズルをさせない
6. **走行計算（`src/car.ts`）は見た目を持たない純粋な計算**。だから `tools/*.ts` でシミュレーションできる
7. **カメラは独立部品**（`src/camera.ts`）。後方視点はプリセットの1つ
8. **スマホ優先**：横持ち、30fps以上。重い描画（影・ポストエフェクト）は入れない

## 6. 進め方のルール（オーナーの方針）
- **クレジット節約が最優先**。1回の依頼で1段階まで。段階が終わったら止めて報告し、オーナーの「進めて」を待つ
- 1つの依頼で1つの機能。変更のたびにビルドが通ることを確認してからコミット
- 同じ不具合に2回失敗したら、直前のコミットに戻す
- 数値の微調整はオーナーが JSON を直接いじる。AIに「いい感じに」を繰り返させない
- 公開リポジトリなので、**パスワード・APIキーは絶対にコードに入れない**
- 返答は日本語。辛口コメント＋根拠＋リスクとリスクヘッジを明示するスタイルが好まれる
